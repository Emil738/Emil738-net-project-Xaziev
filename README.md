## Описание

Проект представляет собой сетевое приложение на C++, состоящее из TCP-сервера и клиента.

Сервер позволяет создавать, просматривать, удалять и изменять пары ключ-значение. Данные можно сохранять в файл `data.txt` и загружать из него, благодаря чему они остаются доступными после перезапуска сервера.

## Как собрать и запустить

Сборка проекта выполнялась в **Visual Studio 2022**.

Для запуска необходимо:

1. Запустить `server.exe`.
2. Запустить `client.exe` в отдельном окне.
3. Вводить команды в окне клиента.

Сначала необходимо запустить сервер, так как клиент подключается к нему.

## Протокол

Сервер слушает порт `9000`. Каждая команда передаётся одной строкой, после чего сервер отправляет одну строку ответа. После подключения сервер присылает приветственное сообщение.

| Команда | Что делает | Пример ответа |
|---|---|---|
| `PING` | Проверяет соединение | `PONG` |
| `SET key value` | Добавляет или изменяет данные | `OK` |
| `GET key` | Получает значение по ключу | `Ivan` |
| `DEL key` | Удаляет данные | `OK` |
| `LIST` | Показывает все данные | `name=Ivan;` |
| `COUNT` | Считает количество пар | `1` |
| `EXISTS key` | Проверяет наличие ключа | `YES` |
| `CLEAR` | Очищает хранилище | `OK` |
| `SAVE` | Сохраняет данные в файл | `OK` |
| `LOAD` | Загружает данные из файла | `OK` |
| `QUIT` | Отключает клиента | `BYE` |

### Обработка ошибок

- Если запрашиваемый ключ отсутствует, сервер отвечает `ERROR not found`.
- Если введена неизвестная команда, сервер отвечает `ERROR unknown command: название_команды`.

## Ответы на контрольные вопросы

### 1. В каком порядке сервер вызывает socket, bind, listen, accept и что делает каждый вызов?

Сначала сервер вызывает `socket()`, чтобы создать сокет для связи. Затем `bind()` привязывает его к определённому порту. После этого `listen()` переводит сервер в режим ожидания подключений. В конце `accept()` принимает подключение клиента и создаёт отдельный сокет для общения с ним.

### 2. Почему клиенту не нужны bind и listen? Какой порт получает клиент?

Клиенту не нужно ждать подключения других устройств, поэтому ему не нужны `bind()` и `listen()`. Он просто подключается к серверу с помощью `connect()`. Система автоматически назначает клиенту свободный временный порт.

### 3. Зачем нужен htons(PORT)?

`htons()` переводит номер порта в сетевой порядок байтов. Это необходимо, чтобы компьютеры одинаково понимали номер порта при сетевом обмене данными.

### 4. Почему recvLine читает до символа \n, а не просто вызывает recv один раз?

Потому что TCP передаёт данные потоком байтов и не сохраняет границы отдельных сообщений. При одном вызове `recv()` можно получить только часть сообщения или сразу несколько частей. Поэтому `recvLine()` читает данные до символа `\n`, который обозначает конец команды.

### 5. Опишите протокол своего варианта: какие команды, какие ответы, что сервер делает при ошибке?

Мой вариант — хранилище данных, в котором информация хранится в виде пар ключ-значение.

Основные команды:

- `SET key value` — добавляет или изменяет данные, ответ `OK`.
- `GET key` — получает значение по ключу.
- `DEL key` — удаляет ключ, ответ `OK`.
- `LIST` — выводит все пары ключ-значение.
- `COUNT` — показывает количество пар.
- `EXISTS key` — проверяет наличие ключа, ответ `YES` или `NO`.
- `CLEAR` — очищает хранилище, ответ `OK`.
- `SAVE` — сохраняет данные в файл `data.txt`, ответ `OK`.
- `LOAD` — загружает данные из файла `data.txt`, ответ `OK`.
- `PING` — проверяет соединение, ответ `PONG`.
- `ECHO text` — возвращает переданный текст.
- `QUIT` — завершает соединение, ответ `BYE`.

Если пользователь запрашивает несуществующий ключ, сервер отвечает `ERROR not found`. Если введена неизвестная команда, сервер возвращает `ERROR unknown command`.
